# Vibe Science v6.0 — Architectural Blueprint

**Codename:** NEXUS (Observe · Recall · Operate)
**Autori:** Carmine Russo + Claude Code (Opus 4.6)
**Data:** 3 marzo 2026
**Input:** v5.5 ORO skill (Codex), v6.0 plugin infrastructure (hooks, DB, pattern extraction), ECC (Everything-Claude-Code) reverse engineering, 21+ sprint di ricerca reale
**Status:** DESIGN DOCUMENT + IMPLEMENTATO
**Relazione con v5.5:** EVOLUTIVO. v6.0 porta tutto v5.5 su Claude Code con 9 innovazioni architetturali. Le 11 leggi diventano 12. I 32 gate restano invariati. L'infrastruttura diventa code-enforced (hooks + DB), non prompt-enforced.

## 1. Executive Summary

### Il problema

Vibe Science v5.5 ORO era progettato per OpenAI Codex. Il passaggio a Claude Code (marzo 2026) ha rivelato tre gap architetturali:

> **Gap 1: Nessuna persistenza cross-sessione.** v5.5 dipendeva da file su disco (STATE.md, TREE-STATE.json). Ma i file da soli non bastano: le decisioni perse, i pattern ricorrenti, le debolezze di R2 — tutto ricominciava da zero ogni sessione.

> **Gap 2: Enforcement solo via prompt.** Le 11 leggi, i 32 gate, le regole R2 — tutto affidato al prompt. Un agente abbastanza creativo poteva soddisfare la lettera senza rispettare lo spirito. Lo SFI e il BFP di v5.0 mitigavano, ma non risolvevano.

> **Gap 3: Nessun apprendimento.** Dopo 21 sprint, l'agente commetteva gli stessi errori. Stessi gate falliti, stesse claim uccise per le stesse ragioni, stesse debolezze di R2. Zero memoria istituzionale.

### La soluzione

v6.0 NEXUS aggiunge **9 innovazioni** che trasformano Vibe Science da un _prompt-based system_ a un _infrastructure-enforced system_:

| # | Innovazione | Problema risolto | Ispirato a |
|---|------------|-----------------|------------|
| 1 | **Hook-Based Enforcement** (5 hooks) | Leggi applicate meccanicamente, non via prompt | Claude Code hook system |
| 2 | **Cross-Session Learning** (pattern extraction) | Stessi errori ripetuti tra sessioni | ECC iterative retrieval |
| 3 | **Instinct Model** (LAW 12) | Nessuna memoria istituzionale | ECC instinct system |
| 4 | **Temporal Decay R2 Calibration** | Calibrazione R2 stale | Bayesian decay models |
| 5 | **PreCompact Context Resilience** | Perdita di contesto dopo compaction | Claude Code PreCompact hook |
| 6 | **Agent Handoff Protocol** | Perdita di contesto tra agenti | ECC handoff documents |
| 7 | **Progressive Context Building** | Cold start lento | SessionStart ~700 token injection |
| 8 | **DB-Backed Research Spine** | Spine solo su file, non cercabile | SQLite + embedding queue |
| 9 | **Claude Code Multi-Agent** (Task tool) | Codex delegation non disponibile | Claude Code Task tool = native BFP |

Inoltre, v5.5 viene portato integralmente:
- 12 leggi (11 da v5.5 + LAW 12 INSTINCT)
- 32 gate (8 schema-enforced, invariati)
- OTAE-Tree loop con DQ1-DQ4, DD0, DC0, L-1
- R2 Ensemble (7 modalita', 4 reviewer)
- SFI, BFP, R3 Judge, Circuit Breaker
- Research Spine, Silent Observer, SSOT
- Serendipity Engine con schema validation

### Cosa NON cambia

- Le 11 Leggi Immutabili restano invariate (ne aggiungiamo una 12a)
- I 32 gate restano — non ne aggiungiamo, non ne rimuoviamo
- I 9 schema JSON restano read-only
- L'architettura OTAE-Tree resta il cuore del loop
- R2 Ensemble (4 reviewer), SFI, BFP, R3 Judge restano
- Il 5-Stage Experiment Manager resta
- L'Agent Permission Model (separation of powers) resta

### Cosa CAMBIA

- **Piattaforma**: OpenAI Codex → Claude Code
- **Modelli**: gpt-5.3-codex → claude-opus-4-6 / claude-sonnet-4-6 / claude-haiku-4-5
- **Enforcement**: prompt-only → hooks + DB + scripts
- **Persistenza**: file-only → file + SQLite (dual storage)
- **Apprendimento**: zero → pattern extraction + instinct model + temporal decay
- **Multi-agent**: Codex delegation → Task tool (native BFP per architettura)
- **Context resilience**: STATE.md only → STATE.md + DB snapshots + PreCompact hook

## 2. Evidence Base

### v5.5 su Codex: cosa funzionava, cosa no

**Funzionava:**
- 32 gate intercettavano errori operativi (DQ1-DQ4 da v5.5)
- R2 Ensemble con SFI e BFP produceva review rigorose
- Research Spine catturava la storia delle decisioni
- Circuit Breaker preveniva deadlock R2-Researcher

**Non funzionava:**
- L'agente dimenticava tutto tra sessioni (cold start ogni volta)
- R2 ripeteva le stesse debolezze (nessuna calibrazione storica)
- Gate failure pattern ricorrenti non venivano riconosciuti
- Transizioni tra agenti perdevano contesto (no handoff formale)
- Se il contesto veniva compattato, l'agente perdeva lo stato attivo

### ECC (Everything-Claude-Code): pattern estratti

Dall'analisi del repository ECC (febbraio 2026), sono stati identificati 16 pattern utili, di cui 6 implementati in v6.0:

| Pattern ECC | Implementazione v6.0 |
|-------------|---------------------|
| Instinct system (atomic behaviors con confidence) | LAW 12 + instinct-model.md |
| Iterative retrieval (memory across sessions) | Pattern extraction + SessionStart injection |
| Agent handoff documents | handoff-protocol.md |
| Progressive context building | SessionStart ~700 token block |
| Temporal decay per calibration data | R2 calibration con exp(-0.02 * weeks) |
| Learned patterns con auto-promotion | GATE_FAILURE_CLUSTER, REPEATED_ACTION, CLAIM_LIFECYCLE, INSTINCT |

## 3. Le 9 Innovazioni

### Innovazione 1: Hook-Based Enforcement

**Problema:** Le leggi di Vibe Science erano applicate solo via prompt. Un agente poteva ignorarle.

**Soluzione:** 5 hook Node.js che si attivano automaticamente sugli eventi di Claude Code:

| Hook | Evento | Cosa fa |
|------|--------|---------|
| **SessionStart** | Inizio sessione | Apre DB, crea session record, inietta contesto progressivo (~700 token) |
| **UserPromptSubmit** | Prima di ogni prompt | Identifica ruolo agente, logga hash prompt, semantic recall |
| **PostToolUse** | Dopo ogni tool | Gate enforcement, permission checks, auto-logging spine, observer checks |
| **Stop** | Fine sessione | Narrative summary, blocca se claim non reviewate, export STATE.md, pattern extraction |
| **PreCompact** | Prima della compaction | Snapshot stato attivo su DB per resilienza |

**Proprieta' critica:** Tutti gli hook degradano gracefully se il DB non e' disponibile. Mai un crash duro — l'infrastruttura non blocca l'agente.

### Innovazione 2: Cross-Session Learning

**Problema:** Dopo 21 sprint, stessi errori ripetuti. Zero memoria.

**Soluzione:** Lo Stop hook estrae pattern cross-sessione:

1. **GATE_FAILURE_CLUSTER** — Stesso gate che fallisce in 2+ sessioni → pattern (es: "DQ1 fallisce quando colonne zero-varianza presenti")
2. **REPEATED_ACTION** — Stessa azione+input in 2+ sessioni → pattern (es: "Stesso bugfix applicato 3 volte")
3. **CLAIM_LIFECYCLE** — Claim uccise per la stessa ragione → pattern (es: "Confounders uccidono la prima claim quantitativa ogni sessione")
4. **INSTINCT** — Comportamento appreso dall'osservazione cross-sessione

Pattern salvati in `research_patterns` DB table con confidence score. Al session start, pattern attivi iniettati nel contesto.

### Innovazione 3: Instinct Model (LAW 12)

**Problema:** L'agente non imparava dai propri errori.

**Soluzione:** Comportamenti atomici con confidence, ispirati al sistema instinct di ECC:

| Stadio | Confidence | Trigger |
|--------|-----------|---------|
| Observation | 0.3 | Pattern notato una volta |
| Pattern | 0.5 | Osservato 3+ volte |
| Instinct | 0.7 | Confermato da evidenza |
| Strong Instinct | 0.9 | Mai contraddetto |

**Decay:** -0.02/settimana (esponenziale). Instinct sotto 0.2 → archiviato.
**Scope:** project (questo RQ) o global (tutti gli RQ).

**LAW 12:** "Learned patterns from past sessions inform current behavior. Instincts are weighted suggestions that decay with time and can be overridden by contradicting evidence."

### Innovazione 4: Temporal Decay R2 Calibration

**Problema:** R2 ripeteva le stesse debolezze. Nessun feedback storico.

**Soluzione:** Le debolezze storiche di R2 sono tracciate con decay esponenziale:

```
weight = exp(-0.02 * ageWeeks)
```

Una debolezza di 50 settimane fa contribuisce solo ~37% del peso originale. Tre stream di dati:
1. **Weakness counts** — Aree dove R2 ha mancato errori
2. **SFI catch rates** — Quanto bene R2 cattura fault iniettati
3. **J0 scores** — Trend dei punteggi del Judge Agent

SessionStart inietta hint come: "R2 ha storicamente mancato 'batch_effect_check' (peso decaduto: 2.3). Priorita' alta."

### Innovazione 5: PreCompact Context Resilience

**Problema:** Quando il contesto viene compattato (auto o manuale), l'agente perde lo stato attivo della ricerca.

**Soluzione:** Il PreCompact hook salva uno snapshot su DB prima della compaction:
- Claim attive e loro status
- Seed di serendipity pendenti
- Conteggio spine entry
- Contenuto STATE.md

Recovery: SessionStart carica l'ultimo snapshot → l'agente ha abbastanza contesto per continuare.

### Innovazione 6: Agent Handoff Protocol

**Problema:** Quando il lavoro passa tra agenti (R2 → Researcher, Explorer → Researcher), si perde contesto.

**Soluzione:** Documenti formali di handoff con 5 sezioni:
1. **Context** — Cosa si stava facendo, quale RQ, stage, cycle
2. **Findings** — Risultati chiave, claim toccate, metriche
3. **Files Modified** — Path con range di righe
4. **Open Questions** — Issue irrisolte
5. **Recommendations** — Prossimi passi suggeriti

### Innovazione 7: Progressive Context Building

**Problema:** Cold start lento — l'agente deve leggere molti file prima di iniziare.

**Soluzione:** SessionStart inietta ~700 token di contesto strutturato:
1. `[STATE]` — Ultimo summary di sessione
2. `[ALERTS]` — Alert dell'observer irrisolti
3. `[R2 CALIBRATION]` — Hint di debolezze storiche
4. `[PATTERNS]` — Pattern cross-sessione con confidence
5. `[PENDING SEEDS]` — Seed di serendipity in attesa

### Innovazione 8: DB-Backed Research Spine

**Problema:** Il Research Spine (SPINE.md) era solo un file su disco. Non cercabile, non indicizzabile.

**Soluzione:** Dual storage:
- **SPINE.md** su disco (human-readable, LAW 10)
- **spine_entries** in DB (cercabile, embedding queue per semantic recall)

PostToolUse auto-crea spine entries per ogni tool invocato. UserPromptSubmit fa vector search per semantic recall.

### Innovazione 9: Claude Code Multi-Agent (Task Tool)

**Problema:** Codex delegation non disponibile. Serve un pattern equivalente per Claude Code.

**Soluzione:** Claude Code Task tool con model tier:

| Ruolo | Modello | Reasoning |
|-------|---------|-----------|
| Researcher | claude-opus-4-6 | high |
| R2-DEEP | claude-opus-4-6 | high |
| R2-INLINE | claude-sonnet-4-6 | medium |
| Observer | claude-haiku-4-5 | low |
| Explorer | claude-sonnet-4-6 | medium |
| R3-Judge | claude-opus-4-6 | high |
| Instinct-Scanner | claude-haiku-4-5 | low |

**Proprieta' architetturale:** R2-DEEP come sub-agent (via Task tool) ha contesto separato. Non vede il ragionamento del Researcher. Questo e' **Blind-First Pass nativo** per architettura — superiore al role-play nello stesso contesto.

### Il plugin avvolge la skill

Il plugin e' l'infrastruttura (hooks + DB + scripts). La skill e' la conoscenza (leggi + gate + protocolli + template). Il plugin avvolge la skill: le hook fanno enforce delle leggi scritte nella skill. La skill senza il plugin funziona comunque (enforcement via prompt), ma con il plugin l'enforcement diventa meccanico.

## 7. Rischi e mitigazioni

| Rischio | Probabilita' | Impatto | Mitigazione |
|---------|-------------|---------|-------------|
| Hook degradation mascherata | Media | Alto | Hook log failure counts in DB; Observer check per staleness |
| Pattern extraction produce rumore | Media | Medio | Soglia confidence 0.5 per promotion; decay automatico sotto 0.2 |
| Temporal decay troppo aggressivo/lento | Bassa | Medio | Lambda configurabile (default -0.02); monitoraggio J0 trend |
| DB corruption | Bassa | Alto | WAL mode, file backup (STATE.md), graceful degradation |
| Instinct model overfitting | Media | Medio | Decay, scope (project vs global), manual override |
| PreCompact snapshot troppo grande | Bassa | Basso | Solo stato essenziale (claim count, seed count, STATE.md) |
